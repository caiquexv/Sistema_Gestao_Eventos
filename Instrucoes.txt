Requisitos de software
PostgreSQL 16 ou superior.
Python 3.11 ou superior.
Ollama instalado localmente, com o modelo qwen3:8b ja baixado.
Bibliotecas Python ollama e psycopg[binary], instaladas a partir do requirements.txt.

Criacao da base
Crie um banco de dados chamado eventos no PostgreSQL. Em seguida execute o DDL que esta na secao 3 do arquivo Projeto.txt. O DDL cria todas as tabelas, as funcoes e as quatro triggers do sistema. Ele foi escrito para rodar em um banco vazio e termina sem erros.

Carga dos dados
Com a base criada, execute o arquivo DML.sql. Ele popula o banco com dados de demonstracao, incluindo series, eventos, atividades, sessoes, espacos, recursos, pessoas, papeis e inscricoes. O arquivo tambem altera a programacao de duas sessoes, o que gera registros na tabela de historico por meio de trigger.

Execucao do prototipo
Entre na pasta Prototipo e instale as dependencias com o comando python -m pip install -r requirements.txt. Confira os dados de conexao e o modelo no arquivo config.json e ajuste apenas esse arquivo caso necessario. Garanta que o Ollama esteja em execucao e que o modelo indicado tenha sido obtido com o comando ollama pull qwen3:8b. Inicie o programa com python main.py.

Uso
O programa apresenta um menu com tres opcoes. A primeira executa qualquer uma das cinco consultas definidas no projeto. A segunda recebe uma pergunta escrita em portugues, envia ao modelo local pelo Ollama, mostra o SQL gerado, executa a consulta em modo somente leitura e apresenta o resultado ou a mensagem de erro. A terceira encerra o programa.

Modelo utilizado no Ollama
qwen3:8b

Limitacoes conhecidas
A conversao de perguntas em SQL depende da qualidade do modelo local e pode, em alguns casos, produzir consultas incorretas, que sao mostradas ao usuario junto com a eventual mensagem de erro do banco. Nao existe interface grafica, pois o enunciado pede uma aplicacao de linha de comando. O controle de vagas nao implementa lista de espera, de modo que inscricoes acima do limite sao apenas recusadas.
