# Organizacao dos arquivos da entrega
Extraia primeiro o ZIP geral da entrega. Na mesma pasta de Projeto.txt, extraia Prototipo.zip para uma subpasta chamada Prototipo. Essa subpasta deve conter main.py, config.json e requirements.txt; Projeto.txt deve permanecer na pasta imediatamente acima, pois o programa utiliza o DDL e as consultas desse arquivo. O config.json distribuido contem parametros de exemplo: preencha-o com os dados do PostgreSQL local antes de iniciar o programa.

# Requisitos de software
PostgreSQL 16 ou superior.
Python 3.11 ou superior.
Ollama instalado localmente, com o modelo qwen2.5-coder:3b ja baixado.
Bibliotecas Python ollama e psycopg[binary], instaladas a partir do requirements.txt.

# Criacao da base:
Crie um banco de dados chamado eventos no PostgreSQL. Em seguida execute o DDL que esta na secao 3 do arquivo Projeto.txt. O DDL cria 21 tabelas, duas views, funcoes e triggers de consistencia temporal, alocacao, recursos e inscricoes/fila, com validacoes auxiliares. Execute-o em um banco vazio.

# Carga dos dados
Com as tabelas criadas e vazias, execute integralmente o arquivo DML.sql uma unica vez. Ele insere 1.686 registros ficticios, incluindo series, eventos, atividades, sessoes, espacos, recursos, pessoas, papeis e inscricoes. Demonstra tambem cancelamento, promocao da fila, reinscricao e reagendamento. Somente a programacao corrente e armazenada, sem historico.

# Execucao do protótipo
Entre na pasta Prototipo e instale as dependencias com o comando python -m pip install -r requirements.txt. Confira os dados de conexao e o modelo no arquivo config.json e ajuste apenas esse arquivo caso necessario. Garanta que o Ollama esteja em execucao e que o modelo indicado tenha sido obtido com o comando ollama pull qwen2.5-coder:3b. Inicie o programa com python main.py.

# Uso
O programa apresenta um menu com tres opcoes. A primeira executa qualquer uma das cinco consultas definidas no projeto. A segunda recebe uma pergunta escrita em portugues, envia ao modelo local pelo Ollama, mostra o SQL gerado, executa a consulta em modo somente leitura e apresenta o resultado ou a mensagem de erro. A terceira encerra o programa.

# Modelo utilizado no Ollama
qwen2.5-coder:3b

# Limitações conhecidas
A conversão de perguntas em SQL depende da qualidade do modelo local e pode produzir consultas incorretas, que são mostradas ao usuário junto com a eventual mensagem de erro do banco. A inferencia por CPU em computadores com pouca memoria pode ser lenta; a primeira pergunta tambem precisa carregar o modelo e processar o esquema.
