INSTRUCOES DE INSTALACAO E EXECUCAO


============================================================

REQUISITOS DE SOFTWARE

============================================================

- PostgreSQL 16 ou superior, com o cliente psql (ou pgAdmin/DBeaver).
- Python 3.11 ou superior.
- Ollama instalado e em execucao, com o modelo qwen2.5-coder:3b baixado.
- Bibliotecas Python ollama e psycopg[binary] (instaladas pelo requirements.txt).

============================================================

PASSO 1 - ORGANIZAR OS ARQUIVOS

============================================================
Extraia Prototipo.zip na MESMA pasta em que esta o Projeto.txt. O main.py
le o DDL do Projeto.txt na pasta imediatamente acima de Prototipo, entao a
estrutura final deve ser:

    <pasta>/Projeto.txt
    <pasta>/DML.sql
    <pasta>/Prototipo/main.py
    <pasta>/Prototipo/config.json
    <pasta>/Prototipo/requirements.txt

============================================================

PASSO 2 - CRIAR O BANCO DE DADOS

============================================================
Crie um banco vazio chamado eventos (nome usado no config.json):

    createdb -U postgres eventos

Ou, no psql / pgAdmin:  CREATE DATABASE eventos;

============================================================

PASSO 3 - CRIAR AS TABELAS (DDL)

============================================================
O DDL esta na secao 3 do Projeto.txt. Ele cria 21 tabelas, 2 views, funcoes
e triggers. Execute-o UMA vez, no banco eventos vazio.

Copie do Projeto.txt o trecho que comeca na linha
    -- Sistema de Gestao de Eventos e Espacos - MER final
e termina na linha
    COMMIT;
(inclusive), SEM as linhas de "=====" que delimitam a secao, e execute no
banco eventos (psql ou Query Tool do pgAdmin).

Alternativa em Linux/macOS (extrai e executa o trecho automaticamente):

    sed -n '/^-- Sistema de Gestao de Eventos e Espacos/,/^COMMIT;$/p' Projeto.txt | psql -U postgres -d eventos -v ON_ERROR_STOP=1

Conferencia: o comando \dt no psql deve listar 21 tabelas.

============================================================

PASSO 4 - CARREGAR OS DADOS (DML)

============================================================
Com as tabelas criadas e vazias, execute o DML.sql inteiro, UMA unica vez:

    psql -U postgres -d eventos -v ON_ERROR_STOP=1 -f DML.sql

Ele insere 1.686 registros ficticios (series, eventos, atividades, sessoes,
espacos, recursos, pessoas, papeis e inscricoes) e demonstra cancelamento,
promocao da fila de espera, reinscricao e reagendamento. Uma segunda execucao
e recusada de proposito, pois as tabelas ja teriam dados.

Conferencia: SELECT count(*) FROM evento;  deve retornar 11.

============================================================

PASSO 5 - EXECUTAR O PROTOTIPO

============================================================
1. Abra um terminal na pasta Prototipo e instale as dependencias:

    python -m pip install -r requirements.txt

2. Confira o config.json. Ele ja vem com os valores abaixo; ajuste somente
   este arquivo, e somente se necessario (usuario, senha, host ou porta):

    banco:   localhost:5432, dbname eventos, user postgres, password postgres
    ollama:  http://localhost:11434, model qwen2.5-coder:3b

3. Garanta que o Ollama esteja em execucao e que o modelo esteja baixado:

    ollama pull qwen2.5-coder:3b

4. Inicie o programa:

    python main.py

============================================================

USO DO PROTOTIPO

============================================================
Menu com tres opcoes:
  1 - Executa uma das 5 consultas do Projeto.txt (escolha o numero 1 a 5).
  2 - Recebe uma pergunta em portugues, envia ao modelo local via Ollama,
      mostra o SQL gerado, executa em modo somente leitura e exibe o
      resultado ou a mensagem de erro.
  3 - Encerra o programa.

============================================================

MODELO UTILIZADO NO OLLAMA

============================================================

qwen2.5-coder:3b

============================================================

LIMITACOES CONHECIDAS

============================================================
- A conversao de perguntas em SQL depende da qualidade do modelo local e
  pode gerar consultas incorretas; nesse caso o SQL e a mensagem de erro do
  banco sao exibidos ao usuario.
- Em computadores sem GPU ou com pouca memoria a inferencia e lenta; a
  primeira pergunta tambem precisa carregar o modelo e processar o esquema.
- O sistema armazena somente a programacao corrente, sem historico
